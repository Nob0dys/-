# 智能报价工作台

正式版 V1 已将原浏览器内演示升级为服务器端报价系统：

- FastAPI 统一执行 Excel 解析、参数优先匹配、单位校验、多制造商方案和导出；
- PostgreSQL 持久化客户、报价任务、报价行、候选选择和审计记录；
- React 工作台支持任务恢复、异常筛选、直接跳页、候选对比和内部/客户双版本导出；
- Docker Compose 可在 Windows 服务器的 Linux 容器环境中运行。

## 本机开发

需要 Node.js 22+ 与 Python 3.12+。

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

另开终端：

```bash
npm ci
npm run dev
```

访问 `http://localhost:3000/`。开发环境初始账号为 `admin / admin123` 与
`quote / quote123`；正式部署必须通过环境变量更换密码。

## Windows 服务器 Docker 部署

1. 安装支持 Linux 容器的 Docker 环境。
2. 将 `.env.example` 复制为 `.env`，修改数据库、管理员和报价员密码。
3. 在项目目录运行：

```powershell
docker compose up -d --build
docker compose ps
```

4. 局域网访问 `http://服务器IP:8080/`。

数据库、上传原件和导出文件分别存放在 Docker 持久化卷中，容器重建不会丢失。`backup`
容器默认每 24 小时将 PostgreSQL 与文件卷备份到 `quote_backups`，保留 14 天；可在
`.env` 中调整 `BACKUP_INTERVAL_SECONDS` 和 `BACKUP_RETENTION_DAYS`。正式上线前应复制一份备份到服务器外，并至少执行一次恢复演练。

查看备份：

```powershell
docker compose exec backup ls -lh /backups
```

恢复时先停止 `api` 和 `worker`，选择明确的备份文件后再执行：

```powershell
docker compose stop api worker
docker compose exec backup pg_restore --clean --if-exists -h postgres -U quotation -d quotation /backups/database-YYYYMMDD-HHMMSS.dump
docker compose start api worker
```

如果修改了 `POSTGRES_USER` 或 `POSTGRES_DB`，恢复命令中也要使用对应值。

## 核心规则

- 匹配权重：参数 45%、型号 15%、名称 15%、制造商/品牌 10%、单位 10%、数据质量 5%。
- 低于 55 分不视为可靠匹配；阻断风险不得批量确认。
- 克/千克、毫升/升等可换算；瓶/盒/套与克等包装单位默认不可换算。
- 每个商品默认推荐 3 个（可选 1–5 个）方案；完全相同的方案不可重复选择，同一制造商的不同报价可同时选择；候选不满意时可新建手工方案。
- 报价任务可不关联客户（一次性报价）；关联 VIP/特殊要求客户时自动应用折扣与要求。
- 客户版导出不会包含内部评分、风险判定和历史来源。

## 历史数据导入（含 .xls 支持）

- 数据治理 → 导入历史报价支持 `.xlsx / .xlsm / .xls`（.xls 通过 xlrd 读取，含公式缓存值）。
- 表头识别支持真实清单变体：`货物名称 / 器材名称 / 设备名称 / 采购品目 / 主要技术参数 / 主要性能要求 / 规格、品名、教学性能要求等`。
- **含税价自动折算**：价格列表头含"含税"（如 普教清单 的"含税单价"）时，导入自动按 `HISTORY_TAX_RATE`（默认 10%）折回税前基准，
  避免导出时再次计税（双重计税）。历史库统一存税前基准。
- 单元格内换行会自动拼接为无空格的产品名称，避免匹配时被插入多余空格。
- 导出的 客户版/内部复核版 会复用原表已有的 数量/单位/品牌/制造商/型号 列，不再重复追加列。

## 税后价格

- 导出（客户版 + 内部复核版 + 方案明细 sheet）新增 **税后单价 / 税后总价**，默认按 10% 税率。
- 税率在**新建报价任务时**设置（可改，本地记忆上次选择），也可在任务详情中随时修改；导出时按 确认单价×(1+税率) 计算（四舍五入 2 位）。

## 匹配规则增强

- 候选池不再"精确同名即独占"：精确同名记录与通用名高分候选合并评分，避免旧系统导出价回灌独大。
- 规格变体一致性：数显/数字 vs 指针、量程/容量（g/ml/mm/A/V）、位数、MF 型号、档位功率不一致会降分并给出"规格变体不符"警告。
- 名称按"核心词"匹配（忽略 高中物理/高中生物 等学科前缀与尾部变体序号，如 游标卡尺1/2）。
- **产品编码（JY 五位码）**：`规格型号`列中的纯 5 位数字自动识别为产品编码（存 `product_code`，不污染 型号 列）；
  询价行参数/型号中的孤立 5 位码也会提取用于精确编码匹配；导出新增「产品编码」列（客户版/内部复核版/明细 sheet）。
- 自动带价门槛：候选与询价的名称核心词相似度 <0.30 或记录核心词未被询价核心词包含时（如 仿真实验↔静电实验箱、条形强磁体↔蹄形强磁体），不自动带价，留待人工复核。
- **赛特尔优先**：候选存在 `赛特尔25年.xls` 记录时默认报价1 选中赛特尔（其余来源仍作备选展示）；
  带 规格变体/量程不符/BLOCK 警告或学段不一致（初中电源 vs 高中电源）的赛特尔候选不默认选中。
- **学段标记**：`高中学生电源` 与 `学生电源` 视为不同产品；学科前缀（高中物理/高中生物…）仍被忽略。
- 注意：**不要**再把旧系统的"内部复核版"导出文件作为历史库导入（其确认价可能是错误匹配的回声）；优先导入 赛特尔/理化生/普教 等真实出价文件。
